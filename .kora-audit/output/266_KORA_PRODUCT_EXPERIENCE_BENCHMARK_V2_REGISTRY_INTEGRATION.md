## 2. S-A / S-B CONTRADICTION — RESOLVED, AND IT WAS MINE

The Implementation Program contained an internal contradiction: it declared *"S-B depends on S-A"* in the package
table while the First Batch described both as **parallel DAG roots**. Both could not become governance truth.

**Adjudication: both are roots.** Verified against technical boundaries, not preference. A surface role is defined by
elevation, border, background, padding and density — **colour and spacing properties, not typographic ones**. A state
component's semantics (`ZERO ≠ NO DATA`, `SUPPRESSED ≠ ERROR`) are structural. Neither requires the type scale to
**exist** in order to be built; both require it to **render well**, which is a convergence at the demonstrator, not a
build dependency.

**My original ordering was a sequencing preference expressed as a hard dependency** — precisely what the DELTA
contract forbids. `139` and `140` are ratified as roots.

## 6. `KORA-WP-128` ADJUDICATION — **ONE PACKAGE, NOT TWO**

The Implementation Program proposed SPLIT. **Adjudicated against that.**

`128` loses the cockpit redesign and Company IA to `143` — work its *presentation-only, remediation-only* contract
could never legitimately own. It retains two responsibilities: **(A)** Company Intelligence Recomposition and
**(B)** Company System Migration.

They are **one coherent package** because they act on the same files, share one acceptance cycle (Gates A–I on Company
Tier A/B), carry one rollback class (presentation-only), and are **sequential rather than parallel** — the programme's
own collision model requires serial execution within the Company lane. A split would produce two packages that can
never run concurrently, adding governance overhead for no parallelism. Removing the cockpit and IA offsets the added
specificity, so `128` does **not** become an XL mega-package.

**No stop condition was triggered; no additional Company package was required.**

**Governance observation, recorded not acted on:** the Section C edge parser and the declaration/trigger parsers read
prose adjacent to their structures, so DELTA authors must avoid bare package ids in annotations on the edge line, and
bolded totals or bare-bold table cells anywhere live. A future hygiene improvement would scope each parser to its own
section. **The checker was not weakened, and no invariant was relaxed to make this delta pass.**
